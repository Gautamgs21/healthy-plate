# Application Enhancement Specification – Personal Health Monitoring System

## 1. Project Objective

I am developing a Personal Health Monitoring Application to monitor my daily health activities, dietary habits, physical fitness, medical investigations, and medication schedule.

I want to enhance the existing application by introducing a comprehensive Dashboard and improving the Health Monitoring module.

**Important:** Work on the existing application and its current architecture. Do not rebuild the application from scratch. Preserve all existing functionalities, design conventions, data structures, and working modules unless a change is explicitly required below.

---

# 2. Post-Login Navigation

Implement the following navigation behaviour:

- After successful login, automatically redirect the user to the **Dashboard**.
- The Dashboard should become the default landing page.
- Ensure that existing authentication and session management remain functional.

---

# 3. Dashboard – Layout and Functional Requirements

The Dashboard should contain four primary sections:

## Container 1: Upcoming Events

Create five expandable cards:

1. Grocery Purchase
2. Medicine Purchase
3. Meal Preparation
4. Exercises
5. Health Check-ups

### Functional Requirements

- Each card should display the next upcoming activity or requirement.
- Clicking a card should expand it to display the relevant upcoming tasks.
- Display dates, pending activities, and relevant descriptions.
- Automatically populate the cards using information already available in the respective application modules.
- Display an appropriate empty state when no upcoming activities exist.

## Container 2: Statistics

Create three statistical cards.

### Card 1: Calorie Statistics

Display the following information:

1. **Calories Burned Today:** Total calories burned through recorded physical activities.
2. **Calories Intake Today:** Total calories consumed through recorded meals.
3. **Net Calories:** Calories consumed minus calories burned.

Calculation:

Net Calories = Calories Intake − Calories Burned

4. **Daily Calorie Target:** Calculate the remaining calorie allowance based on the user's daily calorie target.

5. **Recommendation Engine:** Generate a dynamic recommendation based on the user's calorie intake, calorie expenditure, and target.

Example:

"You need to burn another X calories or reduce your calorie intake by X calories to remain within your daily calorie target."

The recommendation must be calculated dynamically using actual application data. Do not use static or hardcoded recommendations.

### Card 2: Physical Statistics

Display:

- Current Weight (kg)
- Current BMI
- Target BMI
- Target Weight (kg)
- Weight Progress

Include a line graph showing historical weight and BMI trends.

Graph requirements:

- X-axis: Date
- Y-axis: Weight (kg) or BMI
- Display historical records.
- Clearly indicate the target weight/BMI.
- Allow the user to view historical progress.

### Card 3: Health Check Statistics

Create an interactive Health Check Statistics card.

When clicked, open a modal/popup occupying approximately 75% of the available screen area.

The modal should contain four independent monitoring containers.

#### Container 1: Routine Blood and Urine Investigations

Provide a dropdown selector containing:

1. Fasting Blood Sugar (FBS)
2. Post-Prandial Blood Sugar (PPBS)
3. HbA1c
4. Lipid Profile
5. TSH
6. Serum Creatinine
7. eGFR
8. Urine Albumin-Creatinine Ratio (UACR)
9. Liver Function Test (LFT)
10. Vitamin D (25-OH)
11. Vitamin B12
12. Complete Blood Count (CBC)
13. Urine Routine Examination

#### Container 2: Heart and Cardiovascular Monitoring

Dropdown selector:

1. Blood Pressure
2. Resting ECG
3. 2D Echocardiogram
4. Treadmill Test (TMT)

#### Container 3: Eye Monitoring

Dropdown selector:

1. Comprehensive Eye Examination
2. Diabetic Retinal Examination
3. Intraocular Pressure (IOP)
4. Visual Acuity Test

#### Container 4: Lung Monitoring

Dropdown selector:

1. Spirometry / Pulmonary Function Test
2. Chest X-ray
3. Oxygen Saturation (SpO₂)

### Graph and Data Requirements

Each monitoring container must display a line graph based on the selected investigation.

- Provide an independent dropdown selector for each container.
- Changing the selected investigation should dynamically update its corresponding graph.
- Display historical investigation records.
- X-axis should represent the date of investigation.
- Y-axis should represent the recorded result.
- Display units wherever applicable.
- Show reference ranges where clinically appropriate.
- Visually distinguish results outside the reference range.
- Display the latest recorded result and its previous result.
- Include a clear empty state when no historical data is available.

For investigations that do not produce a single continuous numerical value (such as ECG, X-ray, and echocardiogram), provide an appropriate historical report/timeline view instead of forcing them into a line graph.

Do not fabricate missing medical records or test values.

### Card 4: Medicine Statistics

Display a summary of all medicines currently being taken.

Information to display:

| Field | Description |
|---|---|
| Medicine Name | Name of the prescribed medicine |
| Purpose | Medical purpose or condition |
| Dosage | Prescribed dosage |
| Frequency | Daily frequency |
| Timing | Before/after meals or specific time |
| Status | Active or discontinued |

Display the current medication count and provide an option to view the complete medication list.

The data must be retrieved from the existing Medicine/Medication module.

# 5. Data Integration and Application Logic

Ensure that the Dashboard and Health Tab operate using a common data source.

The following integrations are required:

1. Health Check Statistics must retrieve investigation records from the Health Test module.
2. Medicine Statistics must retrieve active medicines from the Medication module.
3. Calorie Statistics must retrieve food intake from the Diet/Food module and exercise records from the Exercise module.
4. Physical Statistics must retrieve historical weight records from the Physical Health module.
5. Upcoming Events must retrieve pending activities from the relevant modules.

### Data Integrity

- Avoid duplicate records.
- Maintain historical medical records.
- Do not overwrite previous investigation results when new results are entered.
- Allow users to update or correct previously entered records, while preserving data integrity.
- Ensure that dates and numerical values are stored in a consistent format.
- Use appropriate units for each medical parameter.
- Handle missing data gracefully.

# 6. UI/UX Requirements

Maintain the existing application's visual identity and design language.

The enhanced Dashboard should be:

- Clean and professional.
- Mobile-responsive.
- Suitable for desktop and mobile browsers.
- Easy to navigate.
- Visually consistent across all modules.

Additional requirements:

1. Use expandable cards for Upcoming Events.
2. Use interactive graphs for statistical information.
3. Use modal-based presentation for Health Check Statistics.
4. Ensure dropdown selectors are fully functional.
5. Provide loading indicators where data retrieval takes time.
6. Provide appropriate empty states and error messages.
7. Avoid overcrowding the Dashboard.
8. Maintain consistent spacing, typography, card dimensions, and alignment.

# 7. Implementation Instructions

Before making changes:

1. Inspect the existing application's complete source code.
2. Identify the current navigation structure and authentication flow.
3. Identify the existing Health, Diet, Exercise, Physical Health, and Medicine modules.
4. Understand the current database structure and data relationships.
5. Identify reusable components and existing graph libraries.

Then implement the requested changes.

**Critical implementation rules:**

- Do not remove or break existing functionalities.
- Do not replace existing data with sample or dummy data.
- Do not create duplicate database tables unnecessarily.
- Reuse existing database structures wherever possible.
- Implement any necessary database changes with backward compatibility.
- Ensure every button, card, dropdown, graph, and navigation element works.
- Do not leave placeholder functionality.
- Do not hardcode statistical calculations.
- Maintain responsive behaviour across different screen sizes.

# 8. Final Testing and Deliverables

After implementation, verify:

1. Successful login redirects to Dashboard.
2. All five Upcoming Events cards expand and display relevant data.
3. Calorie calculations are accurate.
4. Weight and BMI graphs display historical records.
5. Health Check Statistics modal opens and closes correctly.
6. All investigation selectors work independently.
7. Historical medical records are correctly represented.
8. Medicine Statistics displays active medication details.
9. Health Tab contains the complete investigation checklist.
10. Existing application modules continue to work without regression.

**Expected Outcome:**

A fully integrated Personal Health Monitoring Dashboard that provides a consolidated overview of daily health activities, calorie management, physical progress, medical investigation history, and medication management.

The application should function as a long-term personal health monitoring system rather than merely a static health record interface.
